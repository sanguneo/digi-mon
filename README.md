# digi-mon

> 2022 개정 초등 교육과정을 위한 학습 문제 엔진과 국영수 학습 클라이언트

digi-mon은 초등 **국어·영어·수학** 성취기준을 바탕으로 문제, 학습 목표,
단계별 도움말과 채점 근거를 만드는 엔진이다. 같은 교육과정 자료, 옵션,
시드에서는 언제나 같은 문항과 같은 지문값을 만든다.

문제 발급, 채점, 학습지원 자료와 다음 학습 행동 제안은 엔진이 맡고,
과목별 학습지와 어린이용 키우기·꾸미기 경험은 웹 클라이언트가 맡는다.
학습자가 짧은 문제 묶음을 해 보고 자기 공간을 키워 가는 흐름을 제공하되,
교육과정 판단과 게임 보상의 책임은 분리한다.

## 저장소 역할

현재 저장소는 npm workspace 모노레포다. 루트에는 교육과정 코퍼스, 생성기,
검산·채점 로직, JSON Schema, CLI와 HTTP adapter가 있다. `apps/web`은 기본
학습 클라이언트이고 `apps/web-garden`은 어린이용 키우기·꾸미기 클라이언트다.
각 클라이언트는 자체 `package.json`, 테스트와 빌드 경계를 가지며 엔진의
`src/`를 직접 import하지 않는다. 연결 표면은 HTTP API와 `schema/` 계약이다.

전환 구조, 클라이언트 책임과 구현 순서는
[클라이언트 프로젝트 기획서](docs/client-project-plan.md)에 고정한다.

## 왜 만드는가

문제를 무작위로 만들어 주는 것만으로는 학습 엔진이 되기 어렵다. 학습용
시스템에서는 다음 질문에 답할 수 있어야 한다.

- 어떤 교육과정 성취기준을 연습하는 문제인가?
- 같은 문제를 나중에 정확히 다시 만들 수 있는가?
- 학습자에게 정답이나 교사용 정보가 노출되지 않는가?
- 문제와 함께 학습 목표, 원리, 공식 또는 단계별 도움말을 줄 수 있는가?
- 틀린 답을 실제로 틀렸다고 판정하는가?
- 자동 채점하면 안 되는 수행 과제를 억지로 객관식으로 바꾸지 않는가?
- 근거가 부족할 때 숙달도나 진단 결과를 꾸며내지 않는가?
- 이미 본 문항을 다시 내지 않고도 상태 없는 서버로 운영할 수 있는가?

digi-mon은 이 질문들을 생성기 규칙, 버전이 붙은 자료 구조, 지문값 검증,
뮤테이션 검사와 명시적인 실패 방식으로 다룬다.

## 동작 방식

기본 학습 흐름은 다음과 같다.

1. 클라이언트가 교과, 학년군, 성취기준, 난이도, 연습 방식과 문항 수를
   요청한다.
2. 엔진이 조건에 맞는 문제와 학습 목표를 결정적으로 생성한다.
3. 지원되는 문항에는 원리·규칙과 두 단계 도움말이 함께 제공된다.
4. 클라이언트가 시드, 옵션, 지문값과 문항 출처 정보를 보존한다.
5. 학습자의 답안을 같은 계약으로 재생성하여 채점한다.
6. 명시적인 채점 근거를 학습 게이트에 보내면 다음 연습, 보충 학습,
   진도 진행 또는 사람 검토 제안을 받는다.

엔진은 이 과정에서 학습자 세션이나 장기 학습 이력을 저장하지 않는다.
도움말을 언제 공개할지, 어떤 화면을 보여 줄지, 제안을 실제로 실행할지는
클라이언트가 결정한다.

## 조립·데이터 흐름

```text
reference/ + data/
        ↓
src/ontology/ + src/curriculum/
        ↓
src/generators/
        ↓
src/engine/
        ↓
bin/ CLI · src/server/ HTTP adapter
        ↓
apps/web · apps/web-garden · 외부 클라이언트
```

- `src/engine/`은 DOM, 인쇄, 계정, DB와 클라이언트를 모른다.
- `src/generators/`는 승인된 교육과정·어휘·사실 자료만 사용한다.
- 생성기는 난수·문항 확정 같은 engine primitive를 사용하고 registry가 생성기를
  조립한다. 위 화살표는 package import graph가 아니라 결과가 만들어지는 흐름이다.
- `src/server/`는 엔진 결과를 HTTP로 투영하며 장기 상태를 저장하지 않는다.
- 클라이언트는 학습지의 `seed`, `options`, `fingerprint`를 함께 보존한다.
- 학습자용 투영과 정답 제거는 클라이언트가 재구현하지 않고 엔진 결과를 사용한다.

`tools/check-boundaries.mjs`가 엔진과 생성기에 브라우저·인쇄 관심사가 들어오는
회귀를 검사한다.

## 핵심 기능

### 교육과정에 연결된 문제 생성

- 2022 개정 초등 국어·영어·수학 성취기준을 사용한다.
- 성취기준 연결 여부와 실제 평가 주제 연결 여부를 구분한다.
- 자동 채점이 부적절한 작도·태도·수행 기준은 별도로 표시한다.
- 지문·음성·매체처럼 아직 조달되지 않은 자료 요구도 숨기지 않는다.

기준 코퍼스는 저장소 안의 `data/spine/standards.json`과 교육부 고시
국어·수학·영어 별책 Markdown으로 고정한다. 현재 검증 대상은 성취기준 248개와
생성기 193개다.

### 독립 실행

- 다른 저장소를 설치하거나 같은 상위 디렉터리에 둘 필요가 없다.
- CI, 시험, 전체 검증, 명령줄 도구와 HTTP 서버가 이 저장소만 사용한다.
- 내부 스파인과 세 공식 별책의 SHA-256이 고정 계약과 다르면 즉시 실패한다.
- 내부 스파인의 248개 성취기준 코드를 공식 별책의 코드 목록과 직접 대조한다.
- 문제 생성과 채점 중 외부 네트워크나 대규모 언어 모델을 호출하지 않는다.

내부 스파인의 최초 버전에 남은 역사적 데이터 계보와 공개 전 권리 검토 사항은
`PROVENANCE.md`와 `NOTICE.md`에 투명하게 기록한다. 실행 독립성과 출처 기록은
서로 바꾸어 쓰지 않는다.

### 재현 가능한 발급

- 같은 온톨로지, 옵션, 시드는 같은 학습지와 같은 `fingerprint`를 만든다.
- 문항, 옵션, 학습지원 내용 또는 자료 말뭉치가 바뀌면 지문값도 바뀐다.
- 발급 당시 조건과 다른 조건으로 채점을 요청하면 실패한다.
- 고유 문항이 부족할 때 중복이나 낮은 품질 문항으로 채우지 않고 명시적으로
  실패한다.
- 난이도를 생략한 일반 학습지는 교과별 검토 기본 mix를 사용한다. 수학은
  `1/2/3 = 45/45/10`, 국어·영어는 `15/50/35`이며, 호출자가 `difficulty` 또는
  `difficultyMix`를 지정하면 요청값을 그대로 사용한다
  (`src/engine/worksheet.mjs`).

### 반복 노출 방지

클라이언트는 학습자에게 이미 보여 준 12자리 `item.id`를
`excludeItemIds`로 보낼 수 있다. 엔진은 세션을 저장하지 않으면서 해당 문항을
단일 학습지와 모든 병렬 문제지에서 제외한다.

제외 목록도 지문값 계산에 포함되므로, 나중에 채점할 때 같은 목록을 보내야 한다.
외부 제외에는 공개된 문항 식별자를 사용하지만 내부 중복 판정에는 전체
`dedupeKey`를 사용한다.

### 병렬 문제지

같은 평가 조건을 유지하면서 문항이 겹치지 않는 2~8개의 A/B/C형 문제지를
만들 수 있다.

- 모든 형은 같은 성취기준·생성기·난이도 설계를 공유한다.
- 전체 형에서 같은 문항이 다시 나오지 않는다.
- 각 형의 출처 정보로 어떤 형이든 재생성하고 채점할 수 있다.
- 학습자용과 교사용 결과를 분리한다.

### 학습지원 자료

모든 문항에는 학습 목표가 있다. 검토 후보로 작성된 생성기에는 다음 자료도
포함된다.

- 학습할 원리·규칙·전략
- 첫 번째 도움말
- 더 구체적인 두 번째 도움말
- 교사용 관찰점과 개입 제안

학습자용 결과에서는 교사용 정보, 정답과 전체 풀이가 제거된다. 학습지원 자료가
없는 생성기는 없는 도움말을 꾸며내지 않고 `objective-only`로 표시한다.

현재 사고력 연습 6종, 문해 기초 연습 12종과 저학년 수·연산 26종이
`guided-candidate` 자료를 제공한다. 이 표시는 저장소에서 작성한 검토 후보라는
뜻이며, 외부 교과 전문가의 승인을 받았다는 뜻은 아니다.

### 세 가지 연습 방식

| 방식 | 보장하는 동작 | 뜻하지 않는 것 |
|---|---|---|
| `advanced` | 생성기가 선언한 난이도 3 문항만 선택 | 영재 판별, 상위권 판정, 숙달 진단 |
| `thinking-skills-v1` | 검토된 규칙·순서·근거 과제 6종만 선택 | 일반 사고력 점수, 창의성, 전이 능력 |
| `literacy-foundations` | 검토된 문자·문장 부호 기초 과제 12종만 선택 | 읽기 수준, 결손, 독해 진단 |

여러 방식을 함께 요청하면 모든 조건을 동시에 만족하는 생성기만 사용한다.
조건에 맞는 문제가 없을 때 일반 문제로 몰래 대체하지 않는다.

### 채점

- 자동 채점 문항은 정규화한 학습자 답안을 정답 계약과 비교한다.
- 작도·수행 문항은 교사가 평가 기준별 참·거짓 결과를 입력한다.
- 답하지 않은 자동 채점 문항도 완료율과 정확도 계산에서 숨기지 않는다.
- 학습자용 채점 결과에는 제출 원문과 정답 피드백을 기본적으로 노출하지 않는다.
- 누적 표본이 부족하면 정확도 집계값을 `null`로 남긴다.

### 무상태 학습 게이트

학습 게이트는 단일 채점 결과나 클라이언트가 보존한 누적 응답 기록을 받아
다음 행동을 제안한다.

- `practice`: 같은 범위를 더 연습
- `remediate`: 승인된 보충 경로로 연습
- `advance`: 클라이언트가 명시한 다음 범위로 진행
- `await-manual-review`: 사람의 평가가 끝날 때까지 대기

결과에는 정책 개정 번호, 판단 이유 코드, 비식별 근거 요약과 다음 행동이
포함된다. 누적 응답은 성취기준별 30개 미만이면 근거 부족으로 남긴다.

이 결과는 숙달도 판정, 심리 진단, 읽기 수준 진단 또는 학습자 예측이 아니다.

## 엔진과 클라이언트의 책임 경계

digi-mon은 엔진의 책임을 작게 유지한다. 웹 화면, 학습지 출력과 키우기 상태는
이 저장소의 클라이언트가 담당하며, 다음 기능 역시 엔진 밖에 둔다.

- 웹·앱 화면과 사용자 경험
- 인쇄물 편집과 출력
- 계정, 학급 명단과 로그인
- 장기 학습 이력과 세션 저장
- 문제 배정과 일정 관리
- 도움말 공개 시점과 학습 흐름 제어
- 교사의 최종 판단과 개입 실행
- 실시간 대전이나 게임 기능
- 학습자 요청 시 대규모 언어 모델, 이미지 또는 음성 생성

엔진과 웹 클라이언트를 함께 실행하면 학습 화면을 사용할 수 있다.
계정·학급 운영이나 여러 기기 사이의 학습 이력 동기화는 제공하지 않는다.

## 빠른 시작

### 요구 사항

- Node.js 24 이상 (CI 가 검증하는 유일한 버전이다)

별도 교육과정 저장소, 데이터베이스나 외부 서비스는 필요하지 않다.

### 설치와 전체 검증

```bash
npm ci
npm test
npm run verify
```

- `npm test`: 자동화된 동작·계약 시험 실행
- `npm run verify`: 생성기, 오답 검출, 어휘, 난이도, 선수 관계, 자산 요구,
  자료 구조와 검토 산출물 전체 검사

### 명령줄에서 문제 만들기

```bash
node bin/worksheet.mjs --help

node bin/worksheet.mjs \
  --subject math \
  --grade 3-4 \
  --count 10 \
  --seed class-a
```

사고력 연습 문제:

```bash
node bin/worksheet.mjs \
  --subject math \
  --grade 1-2 \
  --modes thinking-skills-v1 \
  --count 6 \
  --seed think-a
```

문해 기초 연습 문제:

```bash
node bin/worksheet.mjs \
  --subject korean \
  --grade 1-2 \
  --modes literacy-foundations \
  --count 6 \
  --seed literacy-a
```

서로 겹치지 않는 세 개의 병렬 문제지:

```bash
node bin/worksheet.mjs \
  --subject math \
  --count 10 \
  --forms 3 \
  --seed class-a
```

출력 파일명에는 학습지 지문값 일부가 들어간다. 같은 교과와 시드를 사용해도
옵션이 다르면 기존 파일을 덮어쓰지 않는다.

## HTTP 서버

교사용 정답과 상세 채점 결과를 보호할 비밀값을 지정해 서버를 시작한다.

```bash
TEACHER_TOKEN='replace-with-a-secret' npm run serve
```

기본 주소는 `http://127.0.0.1:8787`이다. 외부에 공개해야 할 때만 `HOST`를
명시한다.

### 주요 경로

| 요청 | 경로 | 설명 |
|---|---|---|
| `GET` | `/health` | 서버 상태 확인 |
| `GET` | `/v1/subjects` | 지원 교과 조회 |
| `GET` | `/v1/standards` | 성취기준 조회 |
| `GET` | `/v1/generators` | 등록된 생성기 목록 조회 |
| `GET` | `/v1/coverage` | 성취기준 대비 생성기 커버리지 조회 |
| `POST` | `/v1/items` | 특정 성취기준의 개별 문항 발급 |
| `POST` | `/v1/worksheets` | 학습지 발급 |
| `POST` | `/v1/worksheet-forms` | 2~8개 병렬 문제지 발급 |
| `POST` | `/v1/grade` | 지문값을 확인하고 답안 채점 |
| `POST` | `/v1/learning-gate` | 채점 근거에 따른 다음 행동 제안 |
| `GET` | `/v1/prerequisites` | 승인된 선수 관계 조회 |
| `POST` | `/v1/remediation` | 승인된 선수 관계 기반 보충 문제 발급 |
| `POST` | `/v1/accuracy` | 누적 응답 기록에서 정답률·난이도 역전 집계 |

`GET /v1/generators`는 유형 ID와 이름, 과목·학년군·영역·지원 난이도를 제공한다.
학습지와 병렬 문제지 요청에 `generatorIds: ["math.g12.no.s06.add"]`를 보내면
선택한 유형과 나머지 조건을 함께 만족하는 문제만 생성한다. 생략하면 기존 전체
유형 동작을 유지한다. 선택한 유형의 고유 문항이 부족하면 다른 유형으로 채우지 않고
409를 반환한다. 채점에는 발급된 `options`의 유형 선택도 그대로 전달한다.

정답이 포함된 발급이나 상세 채점 결과는 다음 인증이 필요하다.

```text
Authorization: Bearer <TEACHER_TOKEN>
```

서버는 이름과 이메일 대신 128자 이하의 가명 학습자 토큰만 허용하며, 전달받은
응답 기록을 저장하지 않는다.

## 웹 클라이언트

엔진 API를 소비하는 두 독립 workspace가 있다.

- `apps/web` — 과목·문항 수·난이도를 선택하고 진단·맞춤 학습을 실행하는 기본 클라이언트
- `apps/web-garden` — 참여 기반 보상과 과목별 3D 키우기·꾸미기를 더한 어린이용 클라이언트

두 앱은 과목별 학습지와 원리 도움말을 표시한다. 수학은 여러 영역을 섞은 연습과
30·50문항의 쉬운 수와 연산 연습을 고를 수 있고, 문항 수를 100개까지 조절할 수 있다.
국어는 읽고 쓰는 공간, 영어는 짧은 문장 단위의 연습을 제공한다.
영어의 공식 학년군은 3~4학년부터이며, 기초 영어도 이 범위의 쉬운 문제로 시작한다.

어린이 앱은 첫 화면에서 과목·문항 수·문제 유형을 고르고 바로 시작한다. 문항 수는
1~100개를 직접 입력하며, 직접 고른 수는 과목을 바꿔도 유지한다. 유형 목록에는
현재 과목·학년군·영역·난이도에서 생성 가능한 유형만 표시한다. 학년·영역·난이도와
seed는 `학습 설정`에서 조절한다. 일반 연습 시작과 `새 문제 풀기`는 새 seed를
사용하며, 같은 과목의 직전 학습지 문항을 제외한다. `같은 문제 다시 풀기`는
발급된 문제와 순서를 유지하고 답안·진단 결과만 초기화한다. 같은 문항의 키우기
보상은 중복 지급하지 않는다. 입력한 seed를 그대로 재현하려면 설정 안의
`입력한 seed로 생성`을 사용한다.

국어 5~6학년의 띄어쓰기 유형은 잘못 띄어 쓴 문장을 직접 고쳐 쓰는 문제다.
정답 문장을 선택지로 보여 주지 않으며, 바른 띄어쓰기로 쓴 답을 채점한다.

작은 수의 단순 덧셈·뺄셈·곱셈에는 `점으로 생각해 보기`를 펼칠 수 있다.
주어진 수를 점과 묶음으로 나타내되 결과 숫자를 먼저 표시하지 않는다.
그림은 도움말을 펼쳤을 때만 만들며, 지원하지 않는 식에는 기존 설명을 그대로 제공한다.

어린이 앱의 수학 그리기 문제는 손가락·펜으로 그릴 수 있는 영역을 제공한다.
`그리기 시작`을 켰을 때만 그리기 영역이 터치를 사용하며, 마치면 다시 스크롤할 수 있다.
한 획 되돌리기와 전체 지우기를 지원하고, 자를 사용하는 과제는 종이에 그렸다고
확인할 수도 있다. 그림은 현재 화면과 인쇄물에만 남으며 자동 채점하거나 서버로
전송하지 않는다. 기본 웹의 진단 모드에서도 같은 그리기 영역을 사용할 수 있다.

어린이용 앱의 `세상 둘러보기` 또는 `#garden`에서 세 공간을 오갈 수 있다.

- 국어: 싹에서 잎·꽃·열매로 자라는 나무와 식물 정원
- 영어: 물고기를 돌보고 수초와 장식으로 꾸미는 어항
- 수학: 강아지에게 밥을 주고 빗질하며 함께 노는 마당

수학 강아지는 Blender로 직접 제작한 GLB 모델을 사용한다. 몸통·어깨·발과
얼굴을 연결된 형태로 만들고, 귀에는 두께와 굴곡을 더했다. 모델은 수학 세계를
열 때만 불러오며 기존 성장·고개·꼬리·돌봄 동작을 유지한다.
앱 실행에는 Blender가 필요하지 않다. 편집 원본과 재생성 명령은
[`apps/web-garden/art/puppy/README.md`](apps/web-garden/art/puppy/README.md)에 있다.

해당 과목의 서로 다른 문제 세 개에 답할 때마다 장식 하나를 연다.
학습 참여와 돌봄이 함께 쌓이면 모습이 성장하고 다음 목표와 성장 기록이 나타난다.
정답률은 보상에 영향을 주지 않으며, 접속하지 않았다고 시들거나 성장이 줄지 않는다.
획득한 장식·배치·성장은 이름이나 계정 없이 현재 브라우저의 `localStorage`에 저장된다.
기존 정원의 장식과 배치는 국어 정원으로 이전된다.

돌보기는 매번 시작·반응·마무리가 있는 짧은 동작으로 응답한다. 다시 누르면
현재 동작을 새로 시작하며 대기열을 쌓지 않는다. 화면을 다시 열었다고 이전 돌봄을
자동 재생하지 않는다. 움직임 줄이기 설정에서는 움직이는 효과 대신 정지된 반응과
문장으로 알려 준다. 식물·나무·물·물고기의 재질을 구분하면서 렌더링 묶음을 유지한다.

3D 공간은 버튼으로 돌려 볼 수 있고 장식은 이름이 있는 여덟 지점 중 하나에
놓는다. 터치 드래그 없이도 꾸밀 수 있다. 모바일에서는 학습지 묶음 이동과
화면 왕복 중 답안 보존을 지원한다. 브라우저 새로고침 시 학습 답안은 초기화되고,
저장된 키우기 상태만 복원된다.
진단 학습지와 맞춤 후속 학습지의 답안 그룹은 분리돼 서로의 선택을 해제하지 않는다.

```bash
# 터미널 1: 엔진
npm run serve

# 터미널 2: 기본 웹 (http://127.0.0.1:4173)
npm run web:dev

# 또는 어린이용 3D 키우기 (http://127.0.0.1:4273)
npm run garden:dev
```

프로덕션 빌드 후 작은 정원의 same-origin host를 실행하려면:

```bash
npm run garden:build
npm run host -w @digi-mon/web-garden
```

세부 게임 규칙과 개인정보·접근성 경계는
[`apps/web-garden/DESIGN.md`](apps/web-garden/DESIGN.md)에 있다.
학년군별 콘텐츠 방향과 추가 적용 기준은
[국영수 콘텐츠 확장 방향](docs/learning-content-progression.md)에 정리한다.
[3D 디테일과 돌봄 동작](docs/design/companion-art.md),
[시각 원리 도움말](docs/design/concept-aids.md)에서 세부 디자인 계약을 볼 수 있다.

모바일·태블릿 회귀 검사는 Chromium과 WebKit을 사용한다.

```bash
npx playwright install chromium webkit
npx playwright test --config apps/web-garden/playwright.mobile.config.ts
```
