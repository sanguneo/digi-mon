# 별도 교사·학습자 클라이언트 참고 흐름

> 상태: 참고 설계. digi-mon engine의 구현 계획이나 현재 product roadmap이 아니다.
> 학습 게이트 client·교사용 화면·인쇄·저장은 별도 프로젝트에서 구현한다.
> 무상태 gate 추천 계약과 HTTP endpoint는 digi-mon engine이 제공한다.

이 문서는 현재 CLI·HTTP API 위에 별도 client를 만들 때 고려할 수 있는
교사·학습자 경험을 기록한다.
시각 계약은 [`design-system.md`](design-system.md), 토큰은 [`tokens.css`](tokens.css)다.
실물 표본과 브라우저·인쇄 QA는 파일럿 클라이언트 구현의 완료 조건으로 둔다.

여기 적힌 화면은 이 저장소에서 구현하지 않는다. 실제 client가 채택할 범위와
우선순위는 해당 프로젝트가 별도로 결정한다.

## 1. 경계 — 엔진은 건드리지 않는다

`REVIEW.md` §14 가 PDF·인쇄 레이아웃·DOM·브라우저 렌더를 범위에서 영구 제외했고
`tools/check-boundaries.mjs` 가 `src/`·`bin/` 에서 게이트로 막는다. 이 설계는 그 결정을
유지한다. 화면·인쇄·오프라인은 전부 클라이언트 쪽이다.

```text
digi-mon(엔진)            127.0.0.1:8787, 무상태, DB 없음
별도 client 저장소        정적 UI + 필요할 때 얇은 호스트 프로세스
```

**호스트 프로세스가 필요한 이유는 편의가 아니라 두 가지 계약이다.**

1. **엔진에 CORS 도, `OPTIONS` 라우트도 없다.** `createApp` 은 `access-control-*` 헤더를
   내보내지 않고 라우트 표에 `OPTIONS` 가 없으므로 preflight 는 `404` 로 끝난다.
   다른 origin 의 브라우저 클라이언트는 원리적으로 호출할 수 없다. UI 는 반드시
   같은 origin 에서 서빙되어야 한다.
2. **`TEACHER_TOKEN` 이 브라우저에 있으면 안 된다.** 토큰 하나로
   `includeAnswers`·`includeFeedback`·`manualEvaluations`·`/v1/accuracy` 가 전부 열린다.
   학습자 기기는커녕 교사 브라우저의 JS 에도 두지 않는다.

그래서 호스트는 경로를 둘로 가른다.

| 경로 | 토큰 | 허용 |
|---|---|---|
| `/teacher/*` | 호스트가 `Authorization: Bearer` 주입 | 정답본, 피드백, 수동 채점, 복습 |
| `/learner/*` | **주입하지 않음** | 학습자본 조회, `POST /v1/grade`(피드백 없이) |

`/learner/*` 프록시는 `includeAnswers`·`includeFeedback`·`manualEvaluations` 파라미터를
요청에서 제거한 뒤 전달한다. 통과시켜도 엔진이 `403` 을 주지만, 학습자 경로가 교사
파라미터를 실어 나를 수 있다는 사실 자체를 남기지 않는다.

## 2. 최소 흐름 — 화면 다섯 장

```text
교사 기기 (호스트 + 브라우저)                     엔진
  S1 짜기 ──POST /v1/worksheets ×2──────────────> 학습지(정답본 / 학습자본)
      │
  S2 나눠주기 ├─ 인쇄 A4 ───────────────────────> 종이
      │        └─ 학급코드 ──> 학습자 기기(같은 LAN)
      │                          S4 연습 (오프라인) ──제출──> 호스트
      │                                                        ├─POST /v1/grade─> 채점
      │                                                        └─POST /v1/learning-gate
  S3 걷기·돌려주기 <──────────────────────────────────────────────┘
      └─ POST /v1/remediation (수학) ──> 복습 학습지 ──> S2

  S5 검토 인박스 (교사·전문가, 파일 기반. 엔진 호출 없음)
```

다섯 화면은 목표 경험의 전체 경계이지 첫 파일럿의 동시 구현 범위가 아니다.

| 단계 | 구현 화면 | 진입 근거 |
|---|---|---|
| 개인정보 최소 파일럿 | S1, S2 종이 모드, S3의 세션 한정 익명 요약 | 교사가 3분 안에 인쇄하고 결과가 실제 수업 판단을 바꾸는지 확인 |
| 기기 연습 | S4와 S2 기기 모드 | 종이 흐름으로 해결되지 않는 반복 요구와 학교가 승인한 개인정보·망 경계 |
| 콘텐츠 운영 | S5 | 여러 기여자의 검토량이 source control로 감당되지 않는다는 측정 |

S1과 S2 종이 모드보다 작게는 학습지가 아이에게 닿지 않는다. 반대로 첫 파일럿에
학급 코드, 학습자 기기, 오프라인 제출 queue, 검토 인박스를 한꺼번에 넣으면 아직
입증하지 않은 네 제품을 동시에 운영하게 된다.

### 발급의 핵심 — 배정은 DB 행이 아니라 티켓 세 값이다

`POST /v1/worksheets` 응답의 `fingerprint`·`seed`·`options` 를 보존했다가 채점 때 같이
보내야 한다. 다르면 엔진이 `409` 로 거부한다. 호스트는 이 세 값과 학습자본 JSON 을
먼저 교사 소유 파일로 내보낸다. 교사가 작업을 다시 열지 못해 흐름이 반복해서
중단될 때만 SQLite에 저장한다(운영 계약은
[`operational-data-model.md`](../operational-data-model.md)).

기기 연습 client는 learner item의 `id`를 session 이력에 보존하고 다음 발급의
`excludeItemIds`로 보낸다. gate 호출에는 `/v1/grade`의 비식별 집계 또는 client가
보존한 response record만 보내며, 받은 `nextAction`을 실행할지는 client가 결정한다.

호스트는 배정을 만들 때 **같은 seed·옵션으로 두 번 호출한다.**

```text
1) POST /v1/worksheets  includeAnswers=true   -> 교사 정답본(인쇄용 정답·풀이)
2) POST /v1/worksheets  (기본)                -> 학습자본(엔진이 지운 형태 그대로)
3) 두 응답의 fingerprint 가 다르면 배정을 만들지 않고 실패시킨다
```

학습자본을 호스트가 직접 깎지 않는 이유는 명확하다. `stripAnswers` 는 `answer`,
`solution`, `params`, `dedupeKey`, 선택지의 `correct`, `figure.spec` 을 지우는데, 이 로직을
클라이언트가 다시 구현하면 엔진이 한 번 고칠 때마다 정답이 새는 경로가 하나 늘어난다.

## 3. S1 · 학습지 짜기

좌측 성취기준 레일 / 가운데 조건 / 우측 미리보기. 3열이지만 **대시보드가 아니다**.
숫자 타일을 늘어놓지 않고, 모든 수치는 "지금 이 학습지를 낼 수 있는가" 한 질문에만 답한다.

### 성취기준 레일은 커버리지 렌즈다

`GET /v1/subjects` 로 교과·영역 트리를, `GET /v1/standards?subject=&grade=&covered=true`
로 목록과 `generatorCount` 를, `GET /v1/coverage` 로 미충족 기준의 `blockedBy` 를 읽는다.

- 생성기 있는 기준: 선택 가능
- 생성기 없는 기준: 선택 불가 + `blockedBy.kind`/`need` 를 그 자리에 적는다
  (예: `passage · 학년 수준 짧은 글과 중심 내용 정답`)
- `scoringMode: 'manual'` 기준: 배지 `사람이 채점` + `manualReason`

"왜 국어 읽기가 회색인가"에 화면이 직접 답한다. 별도 문서로 보내지 않는다.

### 문항 수는 성취기준당 몇 문항인지로 보여 준다

엔진은 조건에 맞는 성취기준을 고르게 돌린다. 그래서 20문항을 20개 기준에 걸면
기준당 1문항이 되고, 그 학습지의 성취기준별 정답률은 0 아니면 1 이다.

> 실측: seed `design-preview`, 수학 3-4학년군, 24문항 → 성취기준 24종, 기준당 1문항.

그러면 채점 결과의 `weakStandards`(정답률 &lt; 0.6)는 "약한 기준"이 아니라 **틀린 문항
목록**이다. 그 라벨을 그대로 교사에게 보여 주면 한 문항 실수를 학습 결손으로 읽게 만든다.

그래서 S1 은 조건이 바뀔 때마다 `문항 수 ÷ 대상 기준 수` 를 계산해 `dm-meter` 로 띄운다.

| 기준당 문항 | 표시 |
|---|---|
| 3 이상 | 정상 |
| 1~2 | 경고: `성취기준당 N문항 — 결과를 연습 신호로 읽기에 부족하다. 영역·코드를 좁히거나 문항을 늘려라` |

### 용량 부족은 미리 말한다

문항을 다 못 채우면 엔진이 `409` 와 `{requested, produced, shortfall}` 를 준다.
미리보기는 이 응답을 그대로 받아 `최대 N문항까지 가능` 과 `N으로 줄이기` 버튼을 낸다.
"생성 실패" 같은 말은 쓰지 않는다. 실패가 아니라 파라미터 공간의 상한이다.

### seed 는 감추지 않는다

seed 입력의 기본값은 `2026-03-02-3반` 꼴이고, 바로 아래에 한 줄로 적는다.

> 같은 seed·같은 조건이면 언제 다시 눌러도 같은 학습지가 나온다. 잃어버린 학습지를
> 다시 뽑을 수 있고, 옆 반에 다른 문제를 주려면 seed 를 바꾼다.

## 4. S2 · 나눠주기

### 종이 모드 (기본)

기기가 없어도 성립하는 것이 기본값이다. 인쇄 두 벌(학습지, 정답·풀이 별지)을 낸다.
CLI 로도 같은 결과를 얻는다.

```bash
node bin/worksheet.mjs --subject math --grade 3-4 --count 20 --seed 2026-03-02-class-a
# -> out/worksheets/{stamp}.{json,txt,answers.txt}
```

파일명에 fingerprint 앞 12자가 들어가므로 같은 seed 라도 옵션이 다르면 덮어쓰지 않는다.

### 기기 모드

호스트가 배정 티켓에 6자 학급코드를 붙인다. 학습자는 코드와 **번호**만 입력한다.
계정도, 이름도, 이메일도 없다.

```text
learnerId = "{학급코드}-{번호}"   예: c7f2k9-14
```

`learnerId` 는 엔진이 `^[A-Za-z0-9._:-]+$`, 128자 이하로 강제한다. 위 형식은 그 안에 든다.
번호↔학생 대응표는 **교사 기기에만** 남고 엔진에도 학습자 기기에도 가지 않는다.
만 14세 미만 아동의 개인정보 처리 부담을 설계로 없애는 쪽이다(§13).

학습자 기기는 엔진을 직접 부르지 않는다. 호스트가 배정 시점에 받아 둔 학습자본을
정적으로 내려 주므로, 25명이 들어와도 학습지 조회로 인한 엔진 요청은 0건이다.
엔진 트래픽은 제출 때만 생긴다(§9).

## 5. S3 · 걷기와 돌려주기

교사가 결과를 보는 화면. 순위·평균·추이 그래프를 만들지 않는다.

### 자동 채점 문항

`POST /v1/grade` 응답을 그대로 쓴다. `accuracy`(자동 채점 문항 기준),
`completionRate`, `byStandard.{attempted, correct, accuracy}`.

성취기준 줄은 항상 **시도 수를 정답률 옆에 붙여** 적는다.

```text
[4수01-13] 소수의 자릿값     2/3 시도    ← 비율만 쓰지 않는다
[2수03-04] 사각형 그리기     사람이 채점
```

`시도 3회 미만`인 기준에는 "추가 연습 후보" 라벨을 붙이지 않는다. 대신 배지
`표본 부족`. 문구는 "취약"이 아니라 **"추가 연습 후보"** 를 쓴다
(`docs/research/digi-mon-next-improvements.md` §4.4 의 결과 문구 원칙).

### 수동 채점 문항

`format: 'construction'` 은 `scoring: 'manual'` 로 고정되고 자동 정확도 분모에서 빠진다.
교사 화면은 엔진이 준 `rubric` 개수만큼 체크박스를 낸다.

> 실측: `[2수03-04]` 사각형 그리기 → 기준 3개
> (`곧은 선분 4개로 둘러싸였는가` / `네 선분이 모두 이어져 빈틈이 없는가` / `한 개를 그렸는가`)

`manualEvaluations` 는 rubric 과 **같은 길이의 불리언 배열만** 받는다. 길이가 다르면
`400`. 그래서 UI 는 체크박스 개수를 rubric 에서만 만들고 손으로 정하지 않는다.
자유 서술 칸은 두지 않는다 — 엔진이 받지 않고, 저장 계약도 받지 않는다.

### 복습 (수학만)

`POST /v1/remediation` 은 `followLearningOrder` 와 마찬가지로 수학 전용이고
**승인된 선수 간선만** 쓴다(`prerequisitePolicy: 'approved-only'`).

화면은 응답을 그대로 정직하게 편다.

- `plan[]`: `role`(target/prerequisite), `hasGenerator`, `domain`, `gradeBand`
- `skipped[]`: 생성기가 없어 낼 수 없는 기준 — 숨기지 않고 "이건 못 냅니다"로 적는다
- `excludedCandidateStandards[]`: 배지 `검토 중인 후보 간선 — 학습 순서에 쓰지 않음`

국어·영어에는 이 버튼이 아예 없다. 검토된 선수 그래프가 수학에만 있다.

## 6. S4 · 학습자 연습

한 화면에 한 문항. 상단 진행 점, 본문, 하단 답 입력. 타이머·점수·순위 없음.

### 화면 구성

```text
● ● ● ○ ○ ○ ○ ○ ○ ○        진행 점(백분율·시간 아님)
─────────────────────────
  3.  물음에 답하시오.
      33.09에서 소수 첫째 자리 숫자는 무엇입니까?
      [ 도해가 있으면 여기 인라인 SVG ]
─────────────────────────
  [ 답 입력 ]            [ 나중에 ]  [ 다음 ]   ← 56px
```

- `instruction` → `dm-item__instruction`, `stem` → `dm-item__stem`
- 선택형은 `choices[].label`(①)을 형태로 쓰고 선택 상태는 테두리 두께로 표시한다.
  색만으로 선택을 말하지 않는다.
- `나중에`(보류)는 진행 점에 빈 원으로 남는다. 미응답은 오답이 아니다 —
  엔진도 `answered` 와 `correct` 를 나눠서 준다.

### 영어 문항의 언어 표시

영어 문항은 발문이 영어, 선택지가 한국어다(실측: stem `I like apples.`,
선택지 `나는 사과를 좋아합니다.`). 화면은 `lang="en"` 을 stem 에, `lang="ko"` 를
선택지에 붙인다. 화면 낭독기가 한 문장을 두 언어 규칙으로 읽지 않게 한다.

### 제출과 피드백

제출은 세션당 한 번, `POST /v1/grade` 한 번이다. 문항마다 부르지 않는다(§9).

피드백 없는 채점 응답에서 학습자에게 남는 것은 `correct`·`answered`·`accuracy`·
`completionRate`·`byStandard` 다. `expected`·`solution`·`submitted`·`rubric` 은 엔진이
지운다. 그래서 학습자 화면은 이렇게만 말한다.

```text
20문항 중 16문항 맞음.
다시 볼 문항:  4  9  17  20        ← 정답도 풀이도 보여 주지 않는다
[ 다시 풀기 ]
```

정답·풀이는 교사가 S3 에서 연다. 다시 풀기는 같은 학습지의 새 시도이고,
`clientSubmissionId` 가 다르므로 이전 제출을 덮어쓰지 않는다.

## 7. 접근성 상태

WCAG 2.2 를 기준으로 하고, **이 엔진 때문에 생기는 세 가지 상태**를 화면에 명시적으로 만든다.

### 상태 A — `access: 'requires-visual'`

`prepareFigure` 가 두 경우에 이 상태를 만든다. 시각 의존 생성기이거나, 대체 텍스트가
정답을 말할 위험이 있어 **일부러 정보를 뺀** 경우다.

> 실측: `[4수03-04]` 무늬 만들기 문항의 `altText` 는
> `문항에 필요한 도형 또는 시각 자료. 정답이 되는 이름이나 값은 대체 텍스트에 제시하지 않는다.`
> 이고 `accommodation` 은
> `핵심 관계가 그림에만 있다. 촉각 도해나 교사의 동등한 시각 대체 자료가 필요하다.`

이 문항은 화면 낭독기만으로는 **원리적으로 풀 수 없다.** 그것이 정직한 상태다.
클라이언트는 이렇게 다룬다.

1. S1 미리보기가 학습지 단위로 집계한다: `시각 필수 문항 N개 — 대체 자료 준비 필요`
2. S4 는 그 문항에 `accommodation` 문자열을 그대로 띄우고 자동 통과시키지 않는다
3. 대체 자료 없이 조용히 배포되는 경로를 만들지 않는다

### 상태 B — SVG 렌더러가 없는 `figure.kind`

`FIGURE_KINDS` 는 17종, `RENDERERS` 는 15종이다. `measure.container` 와 `array.dots` 는
렌더러가 없다. 현재 이 둘을 내보내는 생성기는 없어서(grep 0건) 실제 사고는 아직 없다.

그래도 클라이언트는 `figure` 는 있는데 `figure.svg` 가 없는 경우를 조용히 넘기지 않는다.
`altText` 카드 + 배지 `그림 없음 — 종이 학습지로` 를 띄우고 교사 화면에 올린다.

### 상태 C — 일반 요건

| 항목 | 처리 |
|---|---|
| 대비 | 본문 4.5:1 이상, 의미 있는 비텍스트 3:1 이상(`design-system.md` §5-1 결함 포함) |
| 조작 대상 | 48px, 학습자 주 조작 56px (WCAG 2.2 SC 2.5.8 최소 24px 을 제품 기준으로 상향) |
| 색 단독 금지 | 정오답·교과·상태 전부 라벨·형태 병기 |
| 키보드 | 선택지 `1`~`5`, 화살표 이동, `Enter` 확정. 포커스 링은 `--dm-border-strong` |
| 동작 | 평가 중 애니메이션 없음. `prefers-reduced-motion` 에서 전체 0ms |
| 확대 | 200% 에서 한 열로 접히고 가로 스크롤 없음 |
| 도해 | 엔진이 이미 `role="img"` 와 `aria-label`(=altText)을 넣는다. 클라이언트는 덮어쓰지 않는다 |

## 8. 인쇄 상태

`@page`·`@media print` 는 `tokens.css` 에만 있다. 엔진에 넣으면 `check-boundaries` 가 잡는다.

| 항목 | 규칙 |
|---|---|
| 용지 | A4, 여백 14/14/16mm |
| 쪽 나눔 | `.dm-item`, `.dm-figure` 는 `break-inside: avoid`. 정답 별지는 `break-before: page` |
| 답란 | 1-2학년군 8mm, 그 밖 6mm (`--dm-print-answer-line*`) |
| 작도 문항 | 60mm 사각 박스 (`worksheet-text.mjs` 의 `DRAW_BOX` 를 지면 치수로 옮긴 것) |
| 도해 | 인라인 SVG → 벡터로 인쇄. `print-color-adjust: exact` 는 도해에만 |
| 배경 | 인쇄에서 `--dm-paper-sunk` 를 흰색으로 되돌린다. 학교 프린터 토너를 바탕에 쓰지 않는다 |
| 흑백 | 교과 accent 는 회색 환산이 겹친다(78/81). 인쇄물은 라벨로만 구분한다 |
| 도장 | 1쪽에 `dm-seal`(seed + fingerprint 앞 12자), 각 문항 캡션에 fingerprint 앞 6자 |

도장이 필요한 이유는 장식이 아니다. 종이로 걷은 답안을 나중에 어떤 티켓으로 채점할지
정하려면 종이에 seed 와 fingerprint 가 찍혀 있어야 한다.

> 미검증: 쪽마다 머리글을 반복시키는 `position: fixed` 의 브라우저별 동작을 이 회차에
> 실측하지 못했다(샌드박스가 Chrome 실행을 차단). 그래서 설계는 **반복에 의존하지 않는**
> 쪽으로 잡았다 — 전체 도장은 1쪽에만, 나머지 쪽은 문항 캡션의 짧은 코드로 식별한다.

## 9. 오프라인 상태

학습자본은 도해까지 인라인된 자족 JSON 이라 오프라인이 기본값이다.

| 상태 | 처리 |
|---|---|
| 배포 | 호스트가 배정 시점에 받아 둔 학습자본을 정적으로 서빙. 학습자 기기 → 엔진 직접 호출 0건 |
| 캐시 | Service Worker 로 셸 precache, 학습지는 IndexedDB 에 `fingerprint` 키로 저장 |
| 풀이 중 | 네트워크 불필요. 응답과 문항별 `elapsedMs` 를 로컬에 적립 |
| 제출 큐 | `{clientSubmissionId, fingerprint, seed, options, responses, elapsedMs, learnerId, at}` |
| `at` 시각 | **제출 버튼을 누른 순간**을 찍는다. 엔진이 ISO 8601 UTC 왕복 일치를 강제하므로 `toISOString()` 결과 그대로 보낸다 |
| 재시도 | 채점은 무상태다(`src/server/grade.mjs`: 요청 때 학습지를 다시 만들어 대조, DB 없음). 같은 요청을 다시 보내도 이중 기록이 생기지 않는다 |
| 배너 | `제출 대기 N건`. 자동으로 사라지지 않고 성공해야 내려간다 |

### 요청량

엔진 rate limit 은 IP 당 60초에 120건이고 초과하면 `429` + `retry-after: 60` 이다.
학습자 트래픽은 전부 호스트를 거치므로 엔진에는 **한 IP** 로 보인다.

| 설계 | 25명 학급의 엔진 요청 |
|---|---|
| 세션당 제출 1회 (채택) | 25건 — 한도 안 |
| 문항마다 제출 | 500건 — `429` 확정 |

그래서 문항별 즉시 채점을 하지 않는다. 이것은 UX 취향이 아니라 용량 계산이다.

### 오류 → 화면

| 응답 | 원인 | 화면 |
|---|---|---|
| `409` fingerprint 불일치 | 엔진·온톨로지·옵션이 바뀌어 같은 학습지를 재생성할 수 없다 | 학습자: `선생님께 종이로 내주세요` + 로컬 답안 보존. 교사: 배정 배지 `재생성 불가`. **조용히 다시 채점하지 않는다** |
| `409` shortfall | 조건 대비 문항 부족 | S1 에서만 발생. `최대 N문항` + 줄이기 버튼 |
| `429` | 한도 초과 | 큐 유지, `retry-after` 만큼 대기 후 자동 재시도. 학습자에게는 `잠시 후 자동으로 보냅니다` |
| `413` | 본문 256KiB 초과 | 교사 배치 전송에서만 발생. 나눠 보낸다 |
| `403` | 토큰 없음/불일치 | 교사 화면에만. `TEACHER_TOKEN` 설정 안내 |
| `400` 문항 번호 오류 | 클라이언트 버그 | 사용자에게 노출하지 않고 로컬 로그 |
| `404` preflight | 다른 origin 에서 호출 | 배포 오류. 같은 origin 규칙 위반 |

## 10. S5 · 검토 인박스

학습지 흐름과 독립이지만, 국어·영어 커버리지는 여기서만 움직인다.

### 지금 있는 큐 — 의미 정렬 후보

`coverage.json` 의 승인 의미 정렬 119/248 과 후보 151/248 의 **차이 32건**이 대상이다.
자산 코퍼스는 아직 구현되지 않았으므로(계약만 설계됨) 지금 열 수 있는 인박스는 이것뿐이다.

한 줄에 하나. 화면은 `generatorId` · `standardCode` · `topicId` · 후보 사유 · 예시 문항
두 개를 나란히 놓고 `승인` / `반려` / `보류` 만 받는다. 승인에는 reviewer 와 근거가
필수다 — 없으면 버튼이 눌리지 않는다.

### 자산 revision 큐 (자산 코퍼스 도입 후)

`docs/asset-procurement.md` 의 상태 기계를 그대로 화면으로 만든다.

```text
candidate -> validation-passed -> review-pending -> approved -> retired
                                        \-> rejected      \-> quarantined
```

검토 영역은 `legal`·`curriculum`·`language`·`answer`·`accessibility`·`security` 여섯이고
curriculum 은 서로 다른 두 명이 필요하다. 화면은 영역별 칩으로 남은 승인을 보여 준다.
자기 생성물 승인은 UI 에서 막고 서버에서 다시 막는다.

### 인박스가 아닌 것

파일 기반이다. 서버도 DB 도 없다. 결정은 append-only JSON 으로 쌓고, 정정은 기존
레코드를 고치지 않고 `supersedes` 를 단 새 레코드로 넣는다.

## 11. 비목표 — 이번에 만들지 않는 것

- **일반 대시보드.** KPI 타일, 리더보드, 학급 순위, 추이 그래프, 예측 점수.
- **학습자 기기의 정답·풀이·`TEACHER_TOKEN`.** 어떤 경로로도.
- **실명 로스터.** 이름·이메일은 엔진이 거부하고 클라이언트도 받지 않는다.
  번호 대응표는 교사 기기에만 둔다.
- **타이머·속도 점수.** `elapsedMs` 는 교사 참고값이고 학습자에게 표시하지 않는다.
- **`/v1/accuracy` 화면.** `MIN_SAMPLES` 가 30 이라 한 학급 한 회차로는 생성기·난이도
  칸이 거의 전부 `null` 이다. 숫자가 없는 화면을 만들지 않는다. 학기 단위 누적이
  생긴 뒤에 만든다.
- **숙달도·진단·능력 추정.** IRT/Rasch/DIF, 오개념 진단, 학습자 프로파일.
- **학습자 요청 경로의 LLM·TTS 호출.**
- **`src/`·`bin/` 의 인쇄·PDF·DOM 코드.** 클라이언트에만 둔다.
- **자산이 필요한 기준의 대체 객관식.** 커버리지를 화면으로 올리지 않는다.
- **문항별 즉시 채점.** §9 의 요청량 계산.

## 12. 단계별 성공 기준 — 관찰 가능한 것만

한 학교 3개 학급, 4주. 전부 세거나 잴 수 있는 것으로 적었다.

- **개인정보 최소 파일럿 gate:** 1, 2, 6, 9, 10, 11, 12
- **기기 연습 gate:** 3, 4, 5, 7, 8. 첫 gate가 통과하고 기기 모드 요구가
  관찰된 뒤에만 측정한다.

| # | 기준 | 측정 |
|---|---|---|
| 1 | 학습지 한 장을 조건 선택부터 인쇄까지 **3분 이내, 클릭 12회 이하** | 교사 5명 관찰, 중앙값 |
| 2 | 같은 seed·옵션 재발급의 fingerprint 일치 **100%** | 호스트 로그 대조 |
| 3 | 제출 성공률 **99% 이상**(오프라인 큐 재생 포함) | 큐 성공/전체 |
| 4 | `429` 로 최종 실패한 제출 **0건** | 호스트 로그 |
| 5 | fingerprint `409` **0건**(파일럿 기간 엔진 핀 고정) | 호스트 로그 |
| 6 | `access: requires-visual` 문항이 대체 자료 없이 배포된 건수 **0건** | S1 집계와 교사 확인 체크 대조 |
| 7 | 학습자 응답 payload·클라이언트 로그의 정답·풀이 문자열 **0건** | 자동 검사 |
| 8 | 이름·이메일 형태가 `learnerId` 로 나간 건수 **0건** | 정규식 게이트 |
| 9 | 인쇄물에서 문항이 쪽 경계로 갈린 건수 **0건** | 인쇄 표본 전수 육안 |
| 10 | 시도 3회 미만인데 '추가 연습 후보' 라벨이 뜬 건수 **0건** | S3 스냅샷 |
| 11 | 수동 채점 문항이 자동 정확도 분모에 섞인 건수 **0건** | 채점 응답 검사 |
| 12 | 교사가 "왜 이 성취기준은 못 내나"를 화면만 보고 답한 비율 **80% 이상** | 인터뷰 |

기준 1·12 는 사람 관찰이고 나머지는 기계로 센다. **학습자 정답률은 성공 기준에 넣지
않았다.** 도구가 좋아서 정답률이 오르는 것과 문항이 쉬워서 오르는 것을 이 표본으로
가릴 수 없다.
