# AI 작성 문항 사람 검토 목록

AI가 쓴 문항(`data/authored/**`)은 사람이 검토하기 전까지 학습지와 문항 생성에 나가지 않는다.
작성 게이트를 모두 통과했지만, PR #2 리뷰를 돌릴 때마다 정답이 둘로 읽히는 애매한 문항이 새로 나왔기
때문이다(2차·3차·4차 리뷰 모두). 기계 게이트로는 이런 문항을 다 걸러 내지 못하므로, 학습지에 내보낼지는
사람이 정한다.

- 문항마다 검토 상태가 있다. 기본값은 '검토 전'이다.
- `data/authored/review-status.json`의 `reviewed`에 오른 문항만 '검토 완료'다.
  `src/generators/authored.mjs`는 검토 완료 문항으로만 생성기를 만든다.
- 지금 검토 완료는 0개다. 코퍼스 31개 파일 3,458문항(국어 22개 파일 2,469문항, 영어 9개 파일 989문항)이
  모두 생성에서 빠진다. 국어·영어 학습지는 손으로 만든 생성기만으로 나간다.
- `test/authoring/authored-review-gate.test.mjs`가 검토 전 문항이 학습지에 나오지 않는 것,
  검토 완료로 바꾼 문항만 나오는 것, 손으로 만든 국어·영어 생성이 그대로인 것을 확인한다.

## 검토 방법

1. 아래 순서대로 문항을 연다. 파일은 `data/authored/<교과>/<성취기준>.json`이고 문항은 `id`로 찾는다.
2. 지시문·지문·정답·오답지·풀이를 읽고 다음을 확인한다.
   - 정답이 하나로만 정해지는가(오답지 가운데 맞다고 볼 수 있는 것이 없는가).
   - 학년에 맞는 낱말과 표기·발음·높임·호응이 규범에 맞는가.
   - 지문이나 지시문이 정답을 드러내지 않는가.
3. 고칠 것이 있으면 문항을 고친다. 고친 문항은 작성 게이트(`checkCandidate`)를 다시 통과해야 하므로
   `npm test`로 확인한다. 고칠 수 없으면 문항을 지운다.
4. 내보내도 되는 문항만 `data/authored/review-status.json`의 `reviewed`에 더한다.

   ```json
   {
     "schema": "digi-mon/authored-review-status@1",
     "reviewed": [
       { "id": "111cb2ecec0d", "reviewer": "검토자 이름", "reviewedAt": "2026-11-12" }
     ]
   }
   ```

   - `id`는 문항 id(12자리 16진수), `reviewer`는 검토한 사람, `reviewedAt`은 YYYY-MM-DD다.
   - 코퍼스에 없는 id나 빈 `reviewer`가 있으면 생성이 오류로 멈춘다. 오타가 조용히 무시되지 않는다.
   - 검토 완료를 되돌리려면 그 줄을 지운다.
5. `npm run verify`로 생성기 수와 검토표 산출물을 다시 만들고 `npm test`가 통과하는지 본다.
   검토 완료 문항이 생기면 그 성취기준의 `<교과>.authored.<성취기준>` 생성기가 다시 등록된다.
