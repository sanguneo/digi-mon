# AI 작성 문항 사람 검토 목록

AI가 쓴 문항(`data/authored/**`)은 사람이 검토하기 전까지 학습지와 문항 생성에 나가지 않는다.
작성 게이트를 모두 통과했지만, PR #2 리뷰를 돌릴 때마다 정답이 둘로 읽히는 애매한 문항이 새로 나왔기
때문이다(2차·3차·4차 리뷰 모두). 기계 게이트로는 이런 문항을 다 걸러 내지 못하므로, 학습지에 내보낼지는
사람이 정한다.

- 문항마다 검토 상태가 있다. 기본값은 '검토 전'이다.
- `data/authored/review-status.json`의 `reviewed`에 오른 문항만 '검토 완료'다.
  `src/generators/authored.mjs`는 검토 완료 문항으로만 생성기를 만든다.
- 승인은 승인한 그때의 내용에만 붙는다. `reviewed` 항목의 `revision`은 승인한 내용의 버전(난이도·지시문·지문·정답·오답지·풀이의
  sha256 앞 16자리)이고, 지금 문항 내용의 버전과 같을 때만 검토 완료다. 승인한 뒤 문항 파일을 고치면(손으로 고쳐도)
  승인은 저절로 풀려 학습지에서 빠지고, 지금 내용을 다시 승인해야 나간다. `revision`이 없는 항목도 검토 전으로 본다.
- 지금 검토 완료는 0개다. 코퍼스 31개 파일 3,458문항(국어 22개 파일 2,469문항, 영어 9개 파일 989문항)이
  모두 생성에서 빠진다. 국어·영어 학습지는 손으로 만든 생성기만으로 나간다.
- `test/authoring/authored-review-gate.test.mjs`가 검토 전 문항이 학습지에 나오지 않는 것,
  검토 완료로 바꾼 문항만 나오는 것, 손으로 만든 국어·영어 생성이 그대로인 것을 확인한다.

## 검토 방법

관리자 화면(아래 '관리자 화면으로 검토하기')을 쓰면 2~4단계를 JSON을 손으로 고치지 않고 할 수 있다.
손으로 할 때의 순서는 다음과 같다.

1. 아래 순서대로 문항을 연다. 파일은 `data/authored/<교과>/<성취기준>.json`이고 문항은 `id`로 찾는다.
2. 지시문·지문·정답·오답지·풀이를 읽고 다음을 확인한다.
   - 정답이 하나로만 정해지는가(오답지 가운데 맞다고 볼 수 있는 것이 없는가).
   - 학년에 맞는 낱말과 표기·발음·높임·호응이 규범에 맞는가.
   - 지문이나 지시문이 정답을 드러내지 않는가.
3. 고칠 것이 있으면 문항을 고친다. 고친 문항은 작성 게이트(`checkCandidate`)를 다시 통과해야 하므로
   `npm test`로 확인한다. 고칠 수 없으면 문항을 지운다.
4. 내보내도 되는 문항만 `data/authored/review-status.json`의 `reviewed`에 더한다.

   ```json
   {
     "schema": "digi-mon/authored-review-status@1",
     "reviewed": [
       { "id": "111cb2ecec0d", "reviewer": "검토자 이름", "reviewedAt": "2026-11-12", "revision": "<내용 버전>" }
     ]
   }
   ```

   - `id`는 문항 id(12자리 16진수), `reviewer`는 검토한 사람, `reviewedAt`은 YYYY-MM-DD다.
   - `revision`은 검토한 내용의 버전이다. 관리자 화면으로 승인하면 저절로 적힌다. 손으로 적을 때는 다음으로 구한다.
     `node --input-type=module -e "import { loadAuthoredCorpus, authoredRevision } from './src/generators/authored.mjs'; const i = loadAuthoredCorpus().flatMap((f) => f.items).find((x) => x.id === process.argv[1]); console.log(authoredRevision(i));" 111cb2ecec0d`
   - 코퍼스에 없는 id나 빈 `reviewer`가 있으면 생성이 오류로 멈춘다. 오타가 조용히 무시되지 않는다.
   - 검토 완료를 되돌리려면 그 줄을 지운다.
   - 학습지에서 뺄 문항은 지우지 않고 `excluded`에 올릴 수도 있다.
     `{ "id", "reviewer", "excludedAt": "YYYY-MM-DD", "reason" }` 꼴이고 `reason`은 없어도 된다.
     같은 id가 `reviewed`와 `excluded`에 함께 있으면 생성이 오류로 멈춘다.
5. `npm run verify`로 생성기 수와 검토표 산출물을 다시 만들고 `npm test`가 통과하는지 본다.
   검토 완료 문항이 생기면 그 성취기준의 `<교과>.authored.<성취기준>` 생성기가 다시 등록된다.

### 관리자 화면으로 검토하기

교사 화면의 '문항 검토' 탭에서 목록을 보고, 문항을 고치고, 승인·고친 뒤 승인·빼기·되돌리기를 한다.
파일을 쓰는 화면이라 내 컴퓨터에서만 켠다.

1. 엔진과 화면을 켠다. `npm run web:dev`는 127.0.0.1에만 열리고, 이 컴퓨터에서 온 요청에만
   교사 토큰(`TEACHER_TOKEN`, 없으면 `e2e-teacher-token`)을 붙인다. 엔진도 같은 토큰으로 켠다.

   ```sh
   # 터미널 1 (PowerShell이면: $env:TEACHER_TOKEN='e2e-teacher-token'; $env:DIGIMON_ADMIN_WRITE='1'; npm run serve)
   TEACHER_TOKEN=e2e-teacher-token DIGIMON_ADMIN_WRITE=1 npm run serve
   # 터미널 2
   npm run web:dev
   ```

2. <http://127.0.0.1:4173>에서 '문항 검토' 탭을 연다.
   폰 같은 다른 기기에서 쓰려면 터미널 2를 `DIGIMON_REVIEW_REMOTE=1 npm run web:dev`로 켜서 외부 접속을 연다
   (PowerShell이면 `$env:DIGIMON_REVIEW_REMOTE='1'; npm run web:dev`).
   이때도 프록시는 다른 기기의 요청에 토큰을 붙이지 않는다. 폰에서 컴퓨터 주소의 4173 포트로 들어가
   '교사 토큰' 칸에 엔진의 `TEACHER_TOKEN`을 직접 적어야 조회·수정이 된다. 토큰 없는 요청은 401,
   `DIGIMON_REVIEW_REMOTE=1` 없이 다른 기기에서 온 요청은 403이다. 입력한 토큰은 그 탭의 메모리에만 있고 저장하지 않는다.
   이 설정에서는 `e2e-teacher-token` 같은 알려진 값 대신 길고 추측하기 어려운 `TEACHER_TOKEN`을 쓴다.
   좁은 화면에서는 목록과 상세가 한 화면씩 번갈아 나오고, 불러오기 오류는 두 화면 위에 뜬다.
   저장하지 않은 수정이 있는데 다른 문항이나 '목록으로'를 누르면 저장하고 이동·수정 버리기·계속 고치기 중에서 고르게 한다.
3. '검토자 이름'을 적는다. 브라우저에 저장되고 승인·빼기를 할 때 `reviewer`로 기록된다. 빈 값이면 서버가 거절한다.
4. 목록은 우선 검토 35문항을 아래 표 순서대로 먼저 보여 주고, 나머지는 교과·성취기준 파일 순서다.
   교과·성취기준·상태·오달 판정으로 거른다. 문항을 열면 이 문서의 '짚은 점'과
   `data/authored/review-notes/*.jsonl`의 오달 판정(`{id, verdict, kind, note}` 한 줄에 하나)을 함께 보여 준다.
5. 고칠 것이 있으면 폼에서 고치고 '저장'이나 '고친 뒤 승인'을 누른다. 서버가 작성 게이트(`checkCandidate`)를 다시 돌려
   통과할 때만 그 문항 하나를 바꾼다. id는 그대로고 다른 문항·순서·파일 포맷도 그대로다.
   통과하지 못하면 게이트 이름과 사유를 그대로 보여 주고 아무것도 쓰지 않는다.
   저장·승인·고친 뒤 승인·빼기·되돌리기는 모두 문항을 열 때 받은 내용 버전을 함께 보낸다. 그사이 다른 탭이나
   다른 검토자가 내용을 바꿨으면 서버가 409로 거절하고, 화면은 '다른 곳에서 이 문항이 바뀌었습니다'를 띄운 뒤
   최신 내용을 다시 불러온다. 고치던 초안은 버리지 않고 필드별로 최신 내용과 비교해 보여 주므로, 확인한 뒤 다시
   저장·승인하거나 '내 초안 버리고 최신 내용 쓰기'를 누른다. 못 본 내용이 승인되는 일은 없다.
   GGW 린터는 묶음 단위로 도는 바깥 실행기라 화면에서는 돌리지 않는다.
6. '빼기'는 문항을 지우지 않고 `review-status.json`의 `excluded`에 올린다. '되돌리기'는 검토 전으로 돌린다.
7. 실행 중인 엔진의 생성기는 부팅 때 만든 것이다. 승인한 문항을 학습지에서 보려면 `npm run serve`를 다시 켠다.

`DIGIMON_ADMIN_WRITE=1`이 없으면 조회만 되고 쓰기 요청은 403이다. 배포 서버에는 이 변수를 넣지 않는다.
교사 토큰이 없거나 틀리면 조회도 403이다.

검토를 마치면 바뀜 파일을 PR로 올린다.

```sh
git switch -c review/2026-11-12-<검토자>
npm run verify            # 생성기 수·검토표 산출물을 다시 만든다
npm test
git add data/authored docs/review REVIEW.md
git commit -m "AI 작성 문항 검토: <범위>"
git push -u origin HEAD
gh pr create --title "AI 작성 문항 검토: <범위>" --body "승인 N·고침 N·제외 N"
```

`git diff -- data/authored`로 바뀐 문항과 상태를 먼저 훑어 보고, 우선 검토 표에서 처리한 줄은 같은 PR에서 정리한다.
