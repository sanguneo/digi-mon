# 4차 검토 수정 지시서

4차 외부 검토(§16, 2026-08-05)가 확정한 수정 항목이다. 이 문서만 읽고 작업을 시작할 수 있게
썼다. 각 항목에 **무엇을 · 어디를 · 어떻게 · 완료 판정**을 적었다. 판정 근거 전문은
`REVIEW.md` §16의 "3차 판정"·"4차 판정" 절에 있다.

**이미 처리된 것 — 이 지시서의 대상이 아니다:**

- **C(문장 자산 조사 분해 오염)** — 4차 검토자가 직접 수정. `korean-sentences.mjs`의
  `TRAILING_PARTICLES`에 복합 조사('에는' 등)·'처럼'·'같이' 등록, '-듯이' 어절 통짜 유지,
  `ONE_SYLLABLE_NOUNS` 9개 보강. 오염 14건 → 0건, 어휘 목록 251/430/571.
- **조사 중복 검사 정밀화** — C 수리의 후폭풍. 정화된 목록에서 '가을'이 뽑히자
  `check-korean`이 `가을을`을 '을을' 중복으로 오탐했다. 겹침 앞부분이 학년군 어휘 낱말이면
  정상으로 보도록 고쳤다(`tools/check-korean.mjs`의 `KNOWN_WORDS`). **참고할 것:** 수리 하나가
  다른 게이트의 잠복 오탐을 깨울 수 있다 — 아래 항목을 수리한 뒤 verify가 엉뚱한 게이트에서
  실패하면 §13의 오탐 원칙으로 판단하라.

나머지 A·B·E·F·G가 이 문서의 범위다.

---

## 작업 규칙 — 어기면 되돌린다

1. **완료 판정은 `npm run verify`를 직접 실행해 종료코드 0으로 한다.** grep 파이프의
   종료코드로 읽지 말 것(§13에 사고 기록이 있다). 출력 마지막의 `check-review-doc` 통과까지 확인.
2. **REVIEW.md의 수치는 손으로 정확히 맞춘다.** 커버리지·생성기 수·분모가 바뀌는 작업이
   있다(A-1). `check-review-doc`가 낡은 수치를 잡아 verify가 실패하니, 실패 메시지가 알려 주는
   실제 값으로 §2·§14를 갱신하면 된다.
3. **게이트 문턱을 완화해서 통과시키지 말 것.** 옳은 코드를 위반이라 부르는 오탐일 때만
   검사기를 고치고, 고칠 때는 §13에 사례를 남긴다.
4. `node -e`로 화살표 함수를 쓰지 말 것(Git Bash가 `>`를 리다이렉트로 먹는다).
   패치·확인 스크립트는 파일로 쓴다.
5. 한 항목 = 한 커밋. 커밋 메시지는 기존 관행(한국어, 무엇을 왜)을 따른다.

근거는 국어 재분류가 세운 기준의 자기 일관성이다(같은 행동 동사는 같은 분류).

## B. 자산 내용 6건

### B-1. 방언 3건 검증·교체 — `src/curriculum/korean-vocab.mjs` `DIALECTS`

- `{ standard: '고구마', dialect: '감재', region: '강원' }` — **틀렸을 가능성이 높다.**
  강원 '감재'는 통상 **감자**다(표에 감자→지슬(제주)이 이미 옳게 있다). 국립국어원
  우리말샘/지역어 자료로 확인하고, '감자→감재(강원)'로 고치거나 항목을 교체한다.
  고치는 경우 표제어 '감자'가 두 번 나오므로 `check-fact-tables`의 중복 검사에 걸리는지
  먼저 확인할 것 — 걸리면 둘 중 하나를 다른 낱말로 교체한다.
- `{ standard: '많이', dialect: '많이나', region: '충청' }` — 근거 박약. 검증 불가면 삭제하고
  검증된 짝으로 교체.
- `{ standard: '수건', dialect: '수군', region: '제주' }` — 확인 불가. 위와 같음.

**원칙:** 방언은 지역민에게 사실성이 바로 노출된다. 사전(우리말샘)에서 지역 표기가 확인되는
짝만 남긴다. 교체 후보를 고를 때도 같은 기준.

**완료 판정:** 표가 12짝 유지(개수가 줄면 방언 생성기의 `capacityNote`·용량 게이트 확인),
verify exit 0.

### B-2. 관용 표현 2건 — 같은 파일 `IDIOMS`

- `'입이 무겁다'`의 meaning을 `'말을 조심해서 옮긴다'` → **`'말을 함부로 옮기지 않는다'`**로.
  현재 문구는 "옮긴다"는 뉘앙스라 부정확하다.
- `'바가지를 긁다'`는 뜻은 맞으나 부부 맥락 표현이다. 초등 문항용으로 교체 권고 —
  예: `{ idiom: '눈코 뜰 새 없다', meaning: '몹시 바쁘다' }`. 교체어가 학년군 어휘를 쓰는지는
  `check-vocabulary`가 판정한다.

### B-3. 영어 예문 복수 정답 2건 — `src/curriculum/english-vocab.mjs` `SENTENCE_CASES`

`'Look at the sun!'`·`'Be careful!'`은 **명령문**이라 마침표도 옳다 — 문장 부호 문항에서
정답이 둘이 된다. 감탄문형(What/How로 시작)만 부호가 확정된다.

- 두 문장을 감탄문형으로 교체한다. 예: `'What a big tree!'` `'How nice!'` —
  단, 쓰는 낱말이 `WORDS_G56`(또는 해당 학년군 목록)에 있어야 한다. 없으면 목록에 추가하지
  말고 있는 낱말로 문장을 다시 짓는다.
- accepts에 `.`을 추가하는 방식은 쓰지 않는다 — kind 라벨('exclamation')과 rule 문구가
  거짓이 된다.

### B-4. 높임 표 회귀 금지 — 코드 변경 없음, 주석 한 줄

`HONORIFICS`에 주체 높임(주무시다)과 객체 높임(드리다·뵙다·여쭈다)이 섞여 있다. 문항의
오답 풀이 이 표 안에서만 뽑히는 동안은 안전하지만, `주시다` 같은 표 밖 높임이 오답 풀에
들어가는 순간 정답이 둘이 된다. `HONORIFICS` 선언부에 이 제약을 주석으로 남겨 회귀를 막는다.

## G. 게이트 보강 2건

### G-1. 화이트리스트 자기승인 탐지 — `tools/check-vocabulary.mjs` 또는 신규 게이트

어휘 화이트리스트는 자산이 스스로 공급하므로, 목록에 어절이 들어가면 게이트가 원리적으로
못 본다(4차 실측: '공을'·'배와' 등 14건이 그렇게 통과했다). 낮은 오탐으로 잡는 법:

> 목록 안에서 **토큰 = 다른 토큰 + 조사** 꼴의 짝을 찾는다. '공을'과 '공'이 함께 있으면
> '공을'은 어절일 확률이 높다. '가을'은 '가'가 목록에 없으므로 걸리지 않는다.

- 위반을 발견하면 실패시키되, 정상 낱말 짝(예: '수박'/'수'같은 우연)이 나오면 예외 목록을
  두고 사유를 주석으로 남긴다(§13 오탐 원칙).
- **게이트를 새로 등록하면** `package.json`의 `verify` 체인에 넣고 REVIEW.md의 게이트 수
  주장(§1·§3·§11)을 갱신해야 한다 — `check-review-doc`가 등록·총수를 검사한다.

### G-2. §9 파생 수치를 표로 이관 — `tools/export-review-tables.mjs`

'최대 병목'·'가장 깊은 기준'이 간선을 고칠 때마다 낡는다(1차 '게이트 6종', 4차 '병목 2→4 동률'
— 같은 부류가 두 번 재발). `docs/review/prerequisites.md`에 이미 두 표가 있으므로:

- REVIEW.md §9의 코드 블록에서 병목·최심 줄을 지우고 검토표 링크로 대체한다.
- 또는 유지하고 싶으면 `check-review-doc`의 expected에 병목 상위 목록 문자열을 추가해
  기계 대조 범위에 넣는다. **둘 중 하나를 택하고 §16에 어느 쪽을 택했는지 남긴다.**
