# AI 문항 작성 파이프라인과 국어·영어 문면 윤문

AI는 문항을 쓰는 도구로만 쓴다. 학습지를 만드는 엔진은 지금처럼 결정적이고
네트워크를 쓰지 않는다. AI가 쓴 후보 문항은 저장소 게이트와 GGW 린터를 통과한
것만 `data/authored/<교과>/<성취기준>.json` 코퍼스에 들어가고, 생성기는 그 코퍼스에서
시드로 문항을 뽑는다.

## 흐름

1. `bin/ai-generate.mjs`가 성취기준, 학년군 어휘(영어는 공식 초등 권장 어휘 800개),
   같은 성취기준의 기존 문항 표본, 문장 규칙을 담아 OpenAI 호환 API에 후보를 요청한다
   (`src/authoring/prompt.mjs`, `src/authoring/llm.mjs`).
2. 후보마다 게이트를 건다(`src/authoring/gates.mjs`). 새 규칙을 만들지 않고
   `npm run verify`가 쓰는 규칙을 그대로 가져다 쓴다.
3. 게이트를 통과한 묶음은 GGW 린터로 한 번 더 검사한다(`src/authoring/ggw.mjs`). 린터는 지시문·지문·정답·오답지·해설을
   모두 읽는다.
4. 남은 문항을 id 순서로 코퍼스 파일에 더한다(`src/authoring/pipeline.mjs`).
5. `src/generators/authored.mjs`가 코퍼스 파일마다 생성기 하나를 만들어 레지스트리에
   올린다. 같은 성취기준의 기존 생성기와 함께 등록되므로 학습지는 두 종류 문항을
   섞어 낸다. 코퍼스가 비어 있으면 생성기도 없다.

## 게이트

| 게이트 | 보는 것 | 출처 |
| --- | --- | --- |
| `schema` | 정답 1개, 서로 다른 오답 3개, 풀이, 난이도 1~3 | `assertAuthoredFile` |
| `contract` | 문항 계약과 정답 검산 | `generateItem`, `validateItem` |
| `korean-text` | 숫자·단위·따옴표 뒤 조사, 조사 중복, 공백, 치환 흔적 | `src/engine/korean-text-checks.mjs` |
| `vocabulary` | 국어 학년군 어휘, 영어 선택지 낱말 목록과 공식 800개 | `src/curriculum/vocabulary-gate.mjs`, `src/authoring/english-official.mjs` |
| `eligibility` | AI 작성 대상 성취기준인지(국어·영어, 자동 채점, 자료 있음, 선택형 허용) | `authoringIneligibility` |
| `answer-leak` | 발문이나 지문에 오답 없이 정답만 드러나는지 | `answerLeak` |
| `duplicate` | 코퍼스나 같은 묶음에 같은 지문이 있는지 | `checkCandidate` |
| `ggw` | GGW 린터의 high·mid 문장 지적 | `polish-lint.ts --scan --json`, `--json` |

GGW 린터는 `~/.agents/skills/general-good-writing/scripts/polish-lint.ts`를 `bun`으로
돌린다. 경로는 `DIGIMON_GGW_LINTER`로 바꿀 수 있다. 린터나 `bun`이 없거나 린터 키가
없으면 이 단계만 건너뛰고 경고를 출력한다. 린터의 문서 짜임 판정(예:
`composed_exercise`)은 문항 묶음에 맞지 않아 쓰지 않고, 문장 단위 지적만 쓴다.
low 지적은 경고로만 남긴다. 교과 용어인 '받침'과 '근거'에 붙는
은유·권위 명사 지적도 탈락시키지 않는다.

정답 비노출은 두 겹이다. 작성 단계의 `answer-leak` 게이트가 문면을 보고, 발급 단계에서는
학습자 응답이 다른 문항과 똑같이 `answer`, `solution`, `params`, 선택지의 `correct`를
지운다(`test/authoring/ai-generate.test.mjs`).

## 실행

실제 생성은 API 키가 있어야 한다. 키는 환경변수로만 받고 저장소나 출력에 남기지 않는다.

```bash
export DIGIMON_LLM_BASE_URL=https://api.example.com/v1   # /chat/completions 앞까지
export DIGIMON_LLM_API_KEY=...
export DIGIMON_LLM_MODEL=...

# 성취기준 하나에 통과 문항 50개를 목표로 쓴다
node bin/ai-generate.mjs --subject korean --grade g34 --standard 4국02-04 --count 50

# 학년군의 자동 채점 성취기준 전부를 돌되 파일은 쓰지 않는다
node bin/ai-generate.mjs --subject english --grade g56 --count 30 --dry-run

# 키 없이, 미리 쓴 후보 파일을 같은 게이트에 통과시킨다(성취기준마다 파일 하나)
node bin/ai-generate.mjs --subject korean --candidates k4-02-04.json --candidates k6-04-03.json

# 쓴 뒤에는 산출물과 문서 수치를 다시 맞춘다
npm run verify
npm test
```

후보 파일은 LLM 응답과 같은 꼴이고, 성취기준 코드와 작성자를 위에 더 적는다.
`model`은 코퍼스 문항의 `provenance.model`에 남는다. `standardCode`가 없으면 `--standard`를 준다.

```json
{"standardCode": "[4국02-04]", "model": "claude-opus-5-5", "items": [{"difficulty": 1, "instruction": "...", "stem": "...", "answer": "...", "distractors": ["...", "...", "..."], "solution": ["..."]}]}
```

| 옵션 | 뜻 |
| --- | --- |
| `--subject` | `korean`, `english`. 수학은 모델 답을 따로 검산할 길이 없어 받지 않는다 |
| `--grade` | `g12`, `g34`, `g56` |
| `--standard` | `4국02-04` 또는 `[4국02-04]`. 빼면 조건에 맞는 성취기준 전부 |
| `--count` | 성취기준마다 받을 통과 문항 수(기본 20) |
| `--batch`, `--rounds` | 한 번에 요청하는 후보 수(기본 20), 요청 횟수 상한(기본 3) |
| `--dry-run` | 코퍼스 파일을 쓰지 않는다 |
| `--json` | 결과를 JSON으로 출력한다. 탈락 문항은 지문과 사유를 함께 싣는다 |
| `--candidates` | LLM 을 부르지 않고 후보 파일을 게이트에 통과시킨다. 여러 번 줄 수 있고 키가 필요 없다 |

출력은 성취기준마다 요청 수, 통과 수, 게이트별 탈락 수, 코퍼스 전후 문항 수와 탈락
예시 다섯 개다. 사람이 채점하는 성취기준, 아직 없는 음성·그림·지문 자료가 있어야 하는
성취기준, 선택지를 내면 안 되는 [6국04-06]은 대상에서 빼고(`authoringIneligibility`), 후보 게이트도
같은 규칙으로 `eligibility` 탈락시킨다. 인증 실패·장애·시간 초과 같은 API 오류는 후보 탈락으로
세지 않는다. 그 성취기준에서 멈추고 앞서 통과한 문항만 쓴 뒤 종료 코드 1로 끝난다.

## 코퍼스 파일

```json
{
  "schema": "digi-mon/authored-items@1",
  "subject": "korean",
  "standardCode": "[4국02-04]",
  "skill": "사실과 의견을 구분하고 의견 비교하기",
  "items": [
    {
      "id": "sha256(성취기준|지문|정답) 앞 12자리",
      "difficulty": 1,
      "instruction": "다음 문장이 사실인지 의견인지 고르시오.",
      "stem": "우리 집 강아지는 다리가 네 개입니다.",
      "answer": "사실",
      "distractors": ["의견", "질문", "명령"],
      "solution": ["다리 수는 세어 보면 확인할 수 있다.", "그러므로 사실을 나타내는 문장이다."],
      "provenance": { "model": "…", "prompt": "digi-mon/authoring-prompt@1" }
    }
  ]
}
```

생성기 id는 `<교과>.authored.<k|e|m><학년>-<영역>-<번호>`다(예: `korean.authored.k4-02-04`).
문항 난이도가 한 가지뿐이면 `single`, 여럿이면 `categorical`로 선언한다. 손으로 고친
파일도 레지스트리를 만들 때 같은 모양 검사를 다시 지난다.

## 국어·영어 문면 윤문

기존 국어·영어 생성기 문면 2,849줄을 GGW 린터(`--json`)와 저장소 표기 검사로 읽고
고쳤다. 린터가 가장 많이 짚은 것은 사전 순서 풀이의 번역투였다(175건).
저장소 표기 검사에는 따옴표 뒤 조사 규칙과 따옴표·조사 띄어쓰기 규칙을 더했다.
국어·영어 문면에서 두 규칙에 걸리는 표기는 지금 0건이다.

| 생성기 | 전 | 후 |
| --- | --- | --- |
| 방언 | '어멍'는 제주 지역에서 쓰는 방언이고 | '어멍'은 제주 지역에서 쓰는 방언이고 |
| 시제 | 미래 표현인 '만날 것입니다'이 알맞다. | 미래 표현인 '만날 것입니다'가 알맞다. |
| 시제 | '내일'는 미래를 나타내는 말이다. | '내일'은 미래를 나타내는 말이다. |
| 사전 순서 | 메뚜기가 신발보다 앞에 오는 까닭은 1번째 글자의 첫 자음이 앞서기 때문이다. | 메뚜기와 신발은 첫째 글자의 첫 자음에서 갈리고, 메뚜기가 먼저 실린다. |
| 사전 순서 | 순서대로 쓰면 메뚜기, 신발, 연필 순서다. | 국어사전에는 메뚜기, 신발, 연필 차례로 실린다. |
| 사전·받침·자모 | 토마토, 가기, 꽃이, 고쳐 / 버리면의 마지막 글자는 | 나무, 주황, 도서관, 의자 (표제어만 낸다) |
| 사실과 의견 | 그 말이 '가장 아름답다' 이다. | 그러므로 의견을 만드는 말은 '가장 아름답다'이다. |
| 비유 | 그러므로 비유가 아님이다. | 그러므로 비유가 쓰이지 않은 문장이다. |
| 비유 | '같이' 로 견주었다 / '솜' 에 견주었다. | '같이'로 견주었다 / '솜'에 견주었다. |
| 고쳐쓰기 | 이 문장을 맞춤법과 띄어쓰기가 모두 바르게 고친 것을 고르시오. | 이 문장의 맞춤법과 띄어쓰기를 모두 바르게 고친 것을 고르시오. |
| 맞춤법 | 받침 ㅎ 을 그대로 적는다 | 받침 ㅎ을 그대로 적는다 |
| 영어 빈칸 | 빈칸에는 'book'가 알맞다. | 빈칸에 알맞은 단어는 'book'이다. |
| 영어 지시문 | '창문을 닫으라고 할 때'에는 'Close the window.'이 알맞다. | 창문을 닫으라고 할 때 쓰는 문장은 'Close the window.'이다. |
| 영어 묻고 답하기 | 'How old are you?'에는 'I am ten years old.'로 답한다. | 'How old are you?'에 알맞은 대답은 'I am ten years old.'이다. |
| 영어 대화 발문 | 주어진 말을 한 사람에게 묻습니다. 내용에 알맞은 대답을 고르시오. | 앞의 말을 한 사람에게 묻습니다. 그 말에 맞는 대답을 고르시오. |
| 영어 대소문자 | 첫 글자 n를 대문자 N로 바꾼다. / Egg이다. | 첫 글자 n을 대문자 N으로 바꾼다. / 바꿔 쓴 낱말은 'Egg'이다. |
| 영어 문장 고치기 | What is your name?이다. | 바르게 고쳐 쓴 문장은 'What is your name?'이다. |
| 영어 문장 뜻 | 해가 밝게 빛납니다. / 그 아이는 내 친구입니다. | 해가 밝습니다. / 그녀는 내 친구입니다. |
| 영어 문장 뜻 | The book is in the desk. (책이 책상 안에 있습니다.) | 뺐다. 'in'은 상자에만 쓴다. |

자모 세기, 받침, 국어사전 순서 문항은 이제 학년군 표제어(생활 어휘와 문항이 가르치는
기본형)에서만 낱말을 고른다. 문장 자산에서 떼어 낸 어절('버리면', '꽃이', '고쳐')을
'낱말'로 내던 것을 막은 대신, 이 네 생성기의 관측 문항 용량이 줄었다.

| 교과 | 관측 용량 전 | 관측 용량 후 |
| --- | --- | --- |
| 국어 | 4,710 | 4,278 |
| 영어 | 441 | 438 |

국어에서는 자모 세기가 247개에서 113개로, 받침 있는 낱말 고르기가 272개에서 112개로,
마지막 글자 받침이 117개에서 49개로, 사전 순서가 1,573개에서 1,503개로 줄었다. 영어는 'in the desk' 문장 3개를 빼서
28개에서 25개가 되었다. 관측 용량은 `data/audit/capacity-check.json`의 600개 표본 고유 문항
수다.

## 일꾼이 쓴 코퍼스

LLM 키가 없어서 작업 모델(claude-opus-5-5)이 후보를 직접 쓰고 `--candidates`로 같은
게이트와 GGW 린터에 통과시켰다. 대상은 이미 생성기가 있는 자동 채점 성취기준 국어 18개,
영어 7개다. [6국04-06] 띄어쓰기는 바른 문장을 선택지에 보여 주지 않고 직접 고쳐 쓰게
하는 유형이라(`test/engine/korean-spacing.test.mjs`) 선택형 코퍼스를 넣지 않았다. 생성기가 없는 기준은 자산 요구(음성·지문·매체)로 막혀 있고, 코퍼스를
넣으면 그 결정을 바꾸게 되므로 이번에는 넣지 않았다.

탈락은 사유를 보고 고쳐 다시 넣었다. 가장 많이 걸린 것은 영어 공식 어휘 800개 밖 낱말
(careful, slowly, raise, hungry, let, Tuesday)과 5~6학년 영어 선택지 낱말 목록 밖 낱말,
학년군 국어 어휘 밖의 한 낱말 선택지, 같은 지문 되풀이, GGW 지적('드러난다' 사물의인화,
'~는 뜻이다' 모델틱, '것입니다' 번역투, 억지비유)이었다. 이미 바른 문장을 지문으로 낸
고쳐쓰기 문항 3개는 정답 노출로 떨어져 뺐다.

| 교과 | 코퍼스 문항 | 관측 용량 전 | 관측 용량 후 |
| --- | --- | --- | --- |
| 국어 | 622 | 4,278 | 4,900 |
| 영어 | 216 | 438 | 654 |

관측 용량은 `data/audit/capacity-check.json` 행을 교과별로 더한 값이다. 코퍼스 생성기 25개가
더해져 생성기는 193개에서 218개가 되었다. 교과 적절성은 게이트가 판정하지 않으므로
사람 검토가 남아 있다.

## 일꾼이 쓴 코퍼스 2바퀴

같은 방식으로 성취기준마다 통과 문항 100개 이상을 목표로 다시 썼다. 대상은 생성기가 있는
자동 채점 성취기준 전부(국어 22개, 영어 9개)다. 1바퀴에서 비어 있던 [2국02-02] 띄어 읽기,
[4국04-02] 국어사전, [4국04-03] 문장 짜임, [6국04-02] 표준어와 방언, [4영01-02]·[4영02-02]
대소문자에도 처음 코퍼스를 넣었다. [6국04-06]과 생성기가 없는 기준은 1바퀴와 같은 까닭으로 뺐다.

유형을 넓혔다. 국어는 낱말 뜻·반대말·포함 관계, 높임말, 문장 고치기, 문장 순서, 직접 쓴 짧은
지문 읽기를, 영어는 우리말 상황에 맞는 문장 고르기, 낱말 대소문자·철자, 대화 응답 고르기를 더했다.

탈락은 사유를 보고 고쳐 다시 넣었다. 많이 걸린 것은 학년군 어휘 밖 한 낱말 선택지(활용형 '바빠도',
'형이' 등), GGW 지적('~것이다' 번역투, "나머지 문장은" 메타안내, '어떤 감각으로' 은유 명사,
'앉아 있' 사물의인화)이었다. 영어는 넣기 전에 공식 800개·학년군 선택지 낱말·정답 노출을 미리
걸렀다. 일꾼 도구 오류로 낱말이 겹쳐 찍힌 문항 50개('꽃이'꽃이는)는 게이트가 못 잡아 코퍼스에서

## 검토 전 차단

PR #2 리뷰를 돌릴 때마다(2차·3차·4차) 정답이 둘로 읽히는 애매한 문항이 새로 나왔다.
게이트를 통과한 문항도 사람이 보기 전에는 학습지에 내지 않는다. 문항마다 검토 상태가 있고
기본값은 '검토 전'이다. 사람이 검토해 `data/authored/review-status.json`의 `reviewed`에 올린 문항만
`src/generators/authored.mjs`가 생성기로 만든다. 지금은 0개라 코퍼스 31개 파일 3,458문항이 모두
생성에서 빠지고, 생성기는 224개에서 193개가 되었다. 국어·영어 학습지는 손으로 만든 생성기만으로
나간다. 검토 순서와 상태를 바꾸는 법은 [authored-review-queue.md](authored-review-queue.md)에 있다.

PR #2 2차 리뷰 뒤 국어 2,469문항을 높임·호응·발음·복수 정답·띄어쓰기 허용 표기 기준으로 전수 훑었다
([korean-audit-2026-11-11.md](korean-audit-2026-11-11.md)). 확실한 오류 34문항은 제자리에서 고쳤고
문항 수는 그대로다. 79문항은 '사람 검토 필요'로 남겼다.

## 남은 일

- AI 작성 3,458문항을 사람이 검토해야 학습지에 나간다. 순서는
  [authored-review-queue.md](authored-review-queue.md)를 따른다.

- `math.g12.no.s01.write-digit`의 풀이에 `'십이'은`처럼 따옴표 뒤 조사 오류가 있다.
  수학 생성기는 다른 작업에서 고치므로 따옴표 규칙은 지금 국어·영어 문면에만 건다.
  수학을 고친 뒤 `subjects` 제한을 풀면 된다.
- 프롬프트에는 GGW 지침의 요약만 들어 있다. 실제 모델 출력의 탈락률을 보고
  `PROMPT_VERSION`을 올려 가며 다듬어야 한다.
- 영어 문면에서 따옴표 친 영어 뒤 조사가 발음과 어긋난 곳이 있다(`'Sit down.'는`, `'lion'를`).
  표기 검사가 영어 낱말 뒤 조사는 보지 않아서 1바퀴 문항에도 남아 있다. 규칙을 더하고 고친다.
- GGW 예외의 '근거'는 '근거', '근거를'만 받는다. '근거로·근거가·근거는'도 교과 용어다.
- [4국05-04] 1바퀴 문항 30개의 발문 '어떤 감각으로'는 지금 린터가 은유 명사로 짚는다.
- 방언 낱말, 관용 표현, 영어 대소문자 지문('aPPLE')처럼 사실·교육 적절성은 사람이 봐야 한다.
